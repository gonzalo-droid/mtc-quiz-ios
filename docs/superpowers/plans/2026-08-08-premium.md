# Premium (UI Only) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Port Android's Premium upsell screen to iOS with exact visual fidelity — hero icon, benefits list, plan-selection area, subscribe/restore buttons, disclaimer, legal links — reachable from both Home's premium star icon and Settings' Premium row (both previously no-ops, deferred to this sub-project).

**Scope, confirmed earlier in this session:** "Solo UI, sin StoreKit real" — no App Store Connect products are configured for this app, so there is no real purchase capability. This mirrors Android's own actual current state: Android's `PremiumRepositoryImpl.loadAvailablePlans()` queries Play Billing for 2 product IDs that aren't configured in Play Console, so `availablePlans` is permanently empty and the real, currently-shipping Android app renders the exact same empty-state message this plan ports (`"No hay planes disponibles en este momento. Intenta más tarde."`, confirmed as the real rendered state, not a hypothetical one, and matching the reference screenshot `docs/screen/premium.png`). This plan does not fabricate mock plan data to show a "populated" screen — that would be less faithful to Android's real current behavior, not more.

**Source of truth:** read directly from the real Android source this session — `configuration/presentation/.../premium/PremiumScreen.kt` (full Composable, exact hex colors, exact Spanish copy), `PremiumViewModel.kt` (confirmed: no `PremiumState`/`PremiumAction` sealed types exist in this module — the ViewModel exposes plain `StateFlow`s directly), `core/domain/model/SubscriptionPlan.kt`, and `PremiumRepositoryImpl.kt` (confirmed the empty-state code path).

## Key simplification this scope enables

Because there is no real purchase backend, `PremiumViewModel` needs **no injected dependencies at all** — no repository, no analytics, no billing launcher. `availablePlans` is a permanent `[]`, `selectedPlan` can therefore never become non-nil through real user plan-selection (there's nothing to select), and Android's own CTA-button logic (`enabled = !isLoading && selectedPlan != null`) already naturally renders the button disabled with zero special-casing needed — this plan ports that logic literally rather than adding an iOS-specific "if no plans, disable" branch that Android doesn't have. `subscribe()` is ported as a real method (for API parity, and as the natural hook for a future real-StoreKit pass) but is unreachable through the UI today since the button it's wired to is always disabled. `restorePurchases()` is honest about the same reality: since there is no real purchase backend to query, it always resolves to the same "not found" message Android's own restore flow would produce in this exact configuration.

`PlanCard` (the populated-state row) is still built, matching Android's real code 1:1 — it's simply never reached by the live app today (since `availablePlans` is always empty), demonstrated only via a `#Preview`, exactly mirroring Android's own two preview variants (populated + already-premium). This isn't building for a hypothetical future; it's a direct, faithful port of existing, already-shipping Android UI code, which is this whole project's purpose.

## Architecture

```
MTCDomain (extend)    ← SubscriptionPlan (Identifiable, Equatable, Sendable) + BillingPeriod enum.
MTCPremiumFeature (new) ← PremiumState/PremiumViewModel (no repository dependency — pure UI state),
                          PremiumView (hero, benefits, plan area, CTA, restore, disclaimer, legal links).
mtcquiz (app target)  ← Route.premium, Home gains a premium star icon (deferred from the Detail and
                          Settings sub-projects specifically for this reason), Settings' Premium row
                          wired for real (was a no-op).
```

Dependency rule unchanged: `MTCPremiumFeature` depends on `MTCDomain` only (no `MTCDesignSystem` needed — this screen's colors are fixed, non-theme-aware literals matching Android's own hardcoded `Color(0xFFFFB300)`-style values, not `MTCColor`'s dynamic light/dark tokens; `PlanCard`/`BenefitItem` are private to this screen, matching Android's own placement of them as private composables inside `PremiumScreen.kt`, not promoted to a design-system module).

## Lesson carried over from prior sub-projects

`@Observable`'s macro expansion needs macOS 14+ declared to compile under plain `swift test`. `MTCPremiumFeature/Package.swift` declares `platforms: [.iOS(.v17)]` only (no `.macOS`, ever) and is verified via `xcodebuild test -destination 'platform=iOS Simulator,name=iPhone 17'` from its first task onward.

## Global Constraints

- Deployment target iOS 17, `platforms: [.iOS(.v17)]` — no `.macOS` entry.
- All UI copy is Spanish, transcribed literally from the real Android strings quoted in this plan (including the legal disclaimer text and the fact that both "Términos de uso" and "Política de privacidad" link to the exact same URL in Android's real source — a likely Android-side bug/TODO, ported as-is, not fixed).
- Colors are fixed literals matching Android's exact hex values, not derived from `MTCColor` — this screen intentionally looks the same regardless of the app's light/dark theme setting, matching Android's own design (a "poster-like" premium upsell, not theme-adaptive chrome).
- Work directly on `master` (no worktree). Commit after each task.
- `MTCPremiumFeature` needs linking into the Xcode app target before the final task's build succeeds — same pattern as every prior new package this session.

```swift
import MTCDomain

public struct PremiumState: Equatable, Sendable {
    public var isPremium: Bool
    public var isLoading: Bool
    public var availablePlans: [MTCDomain.SubscriptionPlan]
    public var selectedPlan: MTCDomain.SubscriptionPlan?
    public var restoreMessage: String?

    public init(
        isPremium: Bool = false,
        isLoading: Bool = false,
        availablePlans: [MTCDomain.SubscriptionPlan] = [],
        selectedPlan: MTCDomain.SubscriptionPlan? = nil,
        restoreMessage: String? = nil
    ) {
        self.isPremium = isPremium
        self.isLoading = isLoading
        self.availablePlans = availablePlans
        self.selectedPlan = selectedPlan
        self.restoreMessage = restoreMessage

}
```

```swift
// Packages/MTCPremiumFeature/Sources/MTCPremiumFeature/PremiumViewModel.swift
import MTCDomain
import Observation

@MainActor
@Observable
public final class PremiumViewModel {
    public private(set) var state = PremiumState()

    public init() {}

    public func selectPlan(_ plan: MTCDomain.SubscriptionPlan) {
        state.selectedPlan = plan
    }

    /// No real purchase backend in this scope — intentional no-op. The button this is wired to
    /// stays disabled in practice, since `state.selectedPlan` can never become non-nil through
    /// real user interaction while `availablePlans` is always empty. Kept as a real method for
    /// API parity with Android and as the natural hook for a future real-StoreKit pass.
    public func subscribe() {}

    public func restorePurchases() {
        state.restoreMessage = "No se encontró ninguna suscripción activa"
    }

    public func clearRestoreMessage() {
        state.restoreMessage = nil
    }
}
```

```swift
public struct PremiumView: View {

        _viewModel = State(initialValue: viewModel)

    public var body: some View {
        ZStack {

                set: { if !$0 { viewModel.clearRestoreMessage() } }

            .font(.title3)
```

- [ ] **Step 2: Add a premium star icon to `HomeView`**

Android shows this icon only `if (!state.isPremium)`. This port has no real purchase state (`isPremium` is permanently false, matching Android's own current unconfigured-products reality — see this plan's Architecture section), so the icon is shown unconditionally, which is behaviorally equivalent to Android's real, permanently-`false` state. Add a new required closure parameter `onOpenPremium: () -> Void`.

**Read the current `HomeView.swift` first** — the Settings + Customize sub-project already added `.navigationTitle(...)`, `.navigationBarTitleDisplayMode(.inline)`, and a `.toolbar { ToolbarItem(placement: .navigationBarTrailing) { Button(action: onOpenSettings) { ... } } }` block with the hamburger icon. Do not create a second `.toolbar` modifier — add a SECOND `ToolbarItem` inside that SAME existing `.toolbar` block, for the premium crown icon. Order matters: place the premium `ToolbarItem` BEFORE the settings one (matching Android's real `TopAppBar actions` order — premium icon first/left, menu icon second/right, within the trailing group). The code below shows the intended END STATE of `HomeView`'s toolbar area, not two separate toolbars to add:

```swift
public struct HomeView: View {
    @State private var viewModel: HomeViewModel
    private let onSelectCategory: (MTCDomain.Category) -> Void
    private let onOpenSettings: () -> Void
    private let onOpenPremium: () -> Void

    public init(
        viewModel: HomeViewModel,
        onSelectCategory: @escaping (MTCDomain.Category) -> Void,
        onOpenSettings: @escaping () -> Void,
        onOpenPremium: @escaping () -> Void
    ) {
        _viewModel = State(initialValue: viewModel)
        self.onSelectCategory = onSelectCategory
        self.onOpenSettings = onOpenSettings
        self.onOpenPremium = onOpenPremium
    }

    public var body: some View {
        ScrollView {
            // ...unchanged existing content...
        }
        .navigationTitle("Simulacro de evaluación - Perú 🇵🇪")
        .navigationBarTitleDisplayMode(.inline)
        .task {
            await viewModel.load()
        }
        .toolbar {
            ToolbarItem(placement: .navigationBarTrailing) {
                Button(action: onOpenPremium) {
                    Image(systemName: "crown.fill")
                        .foregroundStyle(Color(red: 1.0, green: 0.702, blue: 0.0)) // matches PremiumView's premiumGold
                }
            }
            ToolbarItem(placement: .navigationBarTrailing) {
                Button(action: onOpenSettings) {
                    Image(systemName: "line.3.horizontal")
                }
            }
        }
    }
}
```
